Issues Found & Fixed

1 · amplify.yml — Critical deployment misconfiguration

ProblemFix
FIXED Used the old single-frontend schema (version: 1 / frontend:). The cd my-app in preBuild did not carry over to the build phase — each Amplify phase runs in the repo root independently. Migrated to the multi-app schema (applications: / appRoot: my-app). Now all phases automatically execute inside my-app/. baseDirectory is now correctly .next (relative to appRoot).
FIXED baseDirectory: my-app/.next — absolute path from repo root while commands ran in my-app/, creating a path mismatch. Changed to baseDirectory: .next (relative to appRoot: my-app).
FIXED npm ci would fail on peer-dep conflicts from cutting-edge packages. Changed to npm ci --legacy-peer-deps.
FIXED Cache paths were relative to repo root (my-app/node_modules), which would not cache correctly under appRoot. Changed to node_modules/**/* and .next/cache/**/* (both relative to appRoot).

2 · package.json — Non-existent package aliases & scripts

ProblemFix
FIXED typescript: "npm:@typescript/typescript6@^6.0.2" — this npm alias package does not exist on the registry. Replaced with the real stable TypeScript: "typescript": "^5.8.3".
FIXED "typescript-7": "npm:typescript@^7.0.2" — TypeScript 7 does not exist; this caused npm install to fail with ETARGET. Removed entirely.
FIXED dev script used cross-env NEXT_DISABLE_TURBOPACK=1 next dev --webpack — the --webpack flag was removed in Next.js 15+. Simplified to next dev.
FIXED lint/lint:fix/format scripts used oxlint and oxfmt which are not installed as dependencies and would cause CI to fail. Replaced with standard next lint.
NOTE Removed oxlint and oxfmt devDependencies (they referenced non-existent npm packages in the original). Removed from devDependencies.

3 · next.config.js — Invalid config keys

ProblemFix
FIXED allowedDevOrigins is not a valid top-level Next.js config key — Next.js 16 emits an Unrecognized key error during build. Removed entirely.
FIXED eslint: { ignoreDuringBuilds } and typescript: { ignoreBuildErrors } are no longer valid in Next.js 16 config (they emit fatal warnings). Removed both blocks.
FIXED Turbopack workspace-root warning caused by two package-lock.json files in the monorepo (root + my-app/). Added turbopack: { root: __dirname } to pin the workspace root to my-app/.

4 · tsconfig.json — JSX transform misconfiguration

ProblemFix
FIXED "jsx": "preserve" — Next.js 16 mandates "jsx": "react-jsx" (the React automatic runtime). Using preserve breaks the TypeScript type-checker pass during build. Set "jsx": "react-jsx".
FIXED Missing .next/dev/types/**/*.ts include path — Next.js auto-adds this; pre-empted the auto-fix by including it explicitly. Added ".next/dev/types/**/*.ts" to include.

5 · lib/cloudflare.ts — AI SDK v7 API alignment

ProblemFix
CONFIRMED convertToModelMessages, UIMessage, streamText, maxOutputTokens, toUIMessageStreamResponse all exist in ai@7. The original code was correct for the intended SDK version. Retained as-is. File was reverted to its original form after intermediate edits confirmed compatibility.

6 · components/chat-shell.tsx — UI stream parsing for AI SDK v7

ProblemFix
FIXED The readChatText stream parser only handled legacy data: SSE lines with type === "text-delta". The AI SDK v7 UIMessage stream emits lines prefixed 0:"..." (type-0 = text chunk) which would be silently dropped. Added a primary 0: prefix handler that JSON-parses the quoted string value. Legacy data: lines retained as fallback.
